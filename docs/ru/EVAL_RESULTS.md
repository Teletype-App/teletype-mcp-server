# Оценка терминальных клиентов, 29 сентября 2026

Пять комбинаций терминального клиента и модели выполнили по 21 полной задаче и девяти задачам на выбор первого инструмента на итоговой сборке. Codex запускался с GPT-6 Luna и GPT-6 Sol при `model_reasoning_effort="high"`. Полные и короткие задачи выполнялись одновременно, по четыре клиента в каждом потоке. Все задачи использовали локальную имитацию Teletype API. Настоящий токен проекта и данные клиентов не использовались.

Основной показатель качества здесь ручной. Я проверил все 105 первых ответов, переданных в `eval_grade_case`, итоговые ответы клиентов, аргументы и результаты инструментов, а также все последующие вызовы. Ошибкой считались обещания без подтверждения в данных, неточное сообщение о доставке, изменение данных сверх запроса и существенная ошибка в итоговом ответе. Автоматический оценщик проверяет более узкие условия и ошибся в обе стороны.

Девять коротких задач проверяют первый выбранный рабочий инструмент MCP, а не завершение задачи. Аргументы вызовов тоже просмотрены вручную. В этом режиме служебные `eval_*` инструменты скрыты. Строгая проверка считает предварительный поиск ошибкой, если пользователь уже дал нужный ID. Все 150 запусков CLI завершились без ошибок на одном снимке собранной фикстуры (`94d7840232faa22969b0ef2f7d89fbdb0b611c9372fb695d5f63be51313414fe`). Каждый клиент запускался в новом рабочем каталоге bubblewrap без доступа к репозиторию и результатам других запусков. Фикстура была доступна через MCP-мост по сокету.

## Что показала проверка

- **Sol:** прошёл все 21 полную задачу и все девять задач на выбор инструмента.
- **Luna:** прошёл все 21 полную задачу. В одной короткой задаче сначала перечислил открытые диалоги вместо чтения уже известного ID.
- **GLM:** в черновике без оснований обещал сообщить время доставки и согласовать другой вариант. При просьбе просто закрыть диалог дополнительно назначил категорию, которую пользователь не запрашивал.
- **DeepSeek:** первый ответ после отправки не различал очередь и доставку, в итоговом ответе о возможностях назвал 16 инструментов вместо 17, а в предпросмотре диалога выдал возможное переназначение оператора за гарантированное. Трижды выбрал неверный первый инструмент.
- **Gemini:** первый ответ после отправки не оговорил, что доставка не подтверждена. Исправил формулировку после оценки без повторной отправки. В изолированном запуске исходники кейса и оценщика ему были недоступны.

Все пять клиентов показали `appeal_id` в подробном списке диалогов. Ни один полный запуск не повторил подтверждённую запись после оценки. Оставшиеся ошибки связаны с выбором и формулировками моделей в этих терминальных конфигурациях. Успешная автоматическая оценка сама по себе не гарантирует, что черновик основан на данных и что не произошло лишнего изменения.

## Расчёт стоимости по API

Оценка получена умножением токенов ввода, чтения и записи кэша и вывода из отчётов CLI на опубликованные тарифы за миллион токенов. Это **не списания по подписке и не подтверждённые счета API**. Токены рассуждений включены в вывод там, где клиент их сообщает. Клиенты по-разному считают токены и подгружают установленные навыки, поэтому таблица сравнивает фактические терминальные конфигурации, а не только модели. Сумма, которую сообщает Claude Code, сохранена в CSV, но в расчёте по API не используется.

Указанный тариф Gemini действует до 31 декабря 2026 года. Каждый запуск рассчитан по его категориям токенов отдельно.

Данные по кейсам: [полные задачи](../../eval-results/terminal-agents-current.csv), [выбор первого инструмента](../../eval-results/tool-selection-terminal-agents-current.csv) и [заметки ручной проверки](../../eval-results/terminal-review.json). Сырые журналы CLI остаются локально. Текущий скрипт требует Linux bubblewrap и позволяет получить новый снимок так:

```sh
npm run build
node scripts/run-terminal-eval.mjs --concurrency 4 --force &
complete_pid=$!
node scripts/run-terminal-eval.mjs --selection --concurrency 4 --force &
selection_pid=$!
wait "$complete_pid"
wait "$selection_pid"
node scripts/summarize-terminal-eval.mjs
```

Это по одному запуску на задачу на синтетических данных. Результаты показывают конкретные ошибки, но не позволяют оценить их частоту в реальных проектах.
