# Архитектура Teletype MCP Server

## 1. Путь запроса

`teletype-mcp-server` подключает MCP-клиенты к платформе поддержки [Teletype](https://teletype.app) по протоколу [Model Context Protocol (MCP)](https://modelcontextprotocol.io).

```
                      +---------------------------------------+
                      |   AI-клиент (Cursor, Claude, Zed)     |
                      +---------------------------------------+
                                          |
                        [stdio]           |       [Streamable HTTP]
                   (локальный помощник)   |    (multi-tenant сервер)
                                          v
                      +---------------------------------------+
                      |     MCP Protocol & Transport Layer    |
                      +---------------------------------------+
                                          |
                                          v
                      +---------------------------------------+
                      |     AsyncLocalStorage RequestContext   |
                      |  (токен, таймауты, квоты, sandbox)    |
                      +---------------------------------------+
                                          |
                                          v
                      +---------------------------------------+
                      |     Валидация входа и выхода (Ajv)    |
                      +---------------------------------------+
                                          |
                                          v
                      +---------------------------------------+
                      |        Инструменты Teletype           |
                      | (find, lookup, read, send, annotate)  |
                      +---------------------------------------+
                                          |
                                          v
                      +---------------------------------------+
                      |      Лимитер запросов и задержки      |
                      +---------------------------------------+
                                          |
                                          v
                      +---------------------------------------+
                      |          Teletype Public API          |
                      +---------------------------------------+
```

Слой инструментов состоит из следующих частей:

| Файл | Задача |
| --- | --- |
| [`tool-catalog.ts`](../../src/tool-catalog.ts) | Имена, описания, схемы входа и выхода, ключи обработчиков |
| [`conversation-tools.ts`](../../src/conversation-tools.ts), [`messaging-tools.ts`](../../src/messaging-tools.ts), [`workspace-tools.ts`](../../src/workspace-tools.ts) | Операции с диалогами, сообщениями и проектом |
| [`entity-resolver.ts`](../../src/entity-resolver.ts) | Поиск сущностей по имени и кэш метаданных проекта |
| [`candidate-hints.ts`](../../src/candidate-hints.ts) | Общие подсказки с кандидатами для нераспознанных имён |
| [`teletype-api.ts`](../../src/teletype-api.ts) | Запросы к API, загрузка файлов, лимит размера ответа, политика повторов и общая оболочка ответа |
| [`api-contract.ts`](../../src/api-contract.ts) | Проверка ответов Public API с поддержкой новых полей |
| [`tools.ts`](../../src/tools.ts) | Публичный класс `TeletypeTools` и реестр инструментов |
| [`tool-presentation.ts`](../../src/tool-presentation.ts) | Короткий текст ответа MCP-инструмента |

Статичные списки MCP (`tools/list`, `prompts/list`, `resources/list`, `resources/templates/list`) отдают частные подсказки кэша, чтобы хост переиспользовал их в рамках сессии, а не запрашивал заново.

## 2. Архитектурные решения

### ADR-001: Инструменты для задач поддержки

- **Контекст**: в Teletype отдельные методы API отвечают за диалоги, клиентов, сообщения и настройки проекта. Для обычной задачи поддержки часто нужны данные из нескольких методов.
- **Решение**: предоставить 17 инструментов для таких задач, включая `get_capabilities` для карты активных инструментов сервера. Список есть в [README](../../README-ru.md#возможности).
- **Результат**: например, `lookup_client_profile` за один вызов возвращает профиль, заметки, дополнительные поля и недавние диалоги.

### ADR-002: Режимы stdio и HTTP

- **Контекст**: сервер может запускаться как персональный процесс оператора на рабочей станции (`stdio`), так и централизованный сервис в корпоративной сети или облаке (`Streamable HTTP` в Docker).
- **Решение**:
  - **Режим `stdio`**: рассчитан на одного пользователя. Токен читается из окружения (`TELETYPE_API_TOKEN`). Локальные вложения (`attachment_path`) разрешены только при явном флаге `ENABLE_LOCAL_UPLOADS=true` и только внутри заданных директорий (`TELETYPE_ALLOWED_FILE_ROOTS`).
  - **Режим `HTTP`**: многопользовательский (multi-tenant) режим. Токен передается в заголовке `X-Teletype-Api-Token` на каждый запрос. Доступ к локальным файлам сервера (`attachment_path`) категорически запрещен.

### ADR-003: Изоляция контекста запросов через `AsyncLocalStorage`

- **Контекст**: в HTTP-режиме запросы разных проектов обрабатываются параллельно в одном процессе Node.js. Глобальный токен или конфигурация запроса могли бы смешать учётные данные.
- **Решение**: параметры каждого запроса изолируются через `AsyncLocalStorage` в [`src/request-context.ts`](../../src/request-context.ts).
- **Результат**: асинхронные вызовы внутри запроса используют его токен и лимиты. Лимитер HTTP и кэш метаданных используют ключи, вычисленные из токена.

### ADR-004: Подтверждение перед записью

- **Контекст**: ошибочный вызов инструмента может отправить сообщение клиенту или закрыть диалог.
- **Решение**: восемь инструментов записи (`send_reply_to_client`, `create_dialog_by_phone`, `send_whatsapp_template`, `manage_sent_message`, `annotate_client_record`, `resolve_conversation`, `manage_operator_group`, `configure_project_webhook`) требуют `confirm: true` для записи и объявляют `destructiveHint: true`. Параметр `mark_seen: true` у `read_conversation_thread` тоже требует подтверждения. Этот инструмент объявляет `readOnlyHint: false`, поскольку может пометить диалог прочитанным, и `destructiveHint: false`, поскольку такое действие не удаляет данные.
- **Результат**: подтверждение снижает риск случайной записи. За авторизацию и согласие пользователя отвечает MCP-клиент.

### ADR-005: Маскировка данных в логах

- **Контекст**: учётные данные API и сообщения клиентов могут попасть в диагностические записи.
- **Решение**: [`src/log.ts`](../../src/log.ts) удаляет поля с названиями, указывающими на чувствительные данные, и маскирует bearer-токены, токены в параметрах URL и значения `X-Auth-Token` внутри строк. В остальных полях вызывающий код не должен писать исходные данные клиентов.

### ADR-006: Генерация прямых ссылок на веб-интерфейс Teletype

- **Контекст**: оператору нужны ссылки из результатов инструментов на диалоги в Teletype.
- **Решение**: сервер определяет домен проекта (`loadProjectDomain()`) и добавляет ссылки `link_to_dialog` и `link_to_message` в результаты инструментов и ресурсы.

### ADR-007: Промпты и ресурсы

- **Контекст**: нативные MCP-клиенты (Cursor, Claude Desktop, Zed) предоставляют отдельные сценарии работы с промптами и ресурсами вне прямых вызовов инструментов.
- **Решение**:
  - Пять промптов для службы поддержки (`triage-inbox`, `draft-reply`, `client-summary`, `escalate-issue`, `shift-handover`).
  - Статические URI ресурсов с актуальными данными (`teletype://project/status`, `teletype://workspace/metadata`, `teletype://dialogs/unanswered`).
  - Реализованы динамические шаблоны ресурсов RFC 6570 (`teletype://dialogs/{dialogId}`, `teletype://clients/{clientId}`) для прямого контекстного чтения диалогов и карточек клиентов.

### ADR-008: Подсказки аргументов

- **Контекст**: MCP-клиент может запрашивать подсказки при вводе аргументов промптов и параметров ресурсов.
- **Решение**:
  - В рукопожатии сервера объявлена возможность `completions: {}`.
  - Обработчик `completion/complete` в [`src/completions.ts`](../../src/completions.ts) предлагает подсказки по ID каналов проекта, стандартным компонентам системы и тезисам ответов клиенту.

### ADR-009: Два поколения MCP

- **Контекст**: клиенты используют рукопожатие `initialize` версии 2025 или `server/discover` версии 2026-07-28.
- **Решение**: SDK v2 регистрирует инструменты через `McpServer.registerTool`. `serveStdio` обслуживает оба поколения. `createMcpHandler` обслуживает новые запросы и старые запросы без хранения сеанса.
- **Результат**: HTTP и stdio предоставляют одинаковые инструменты, промпты и ресурсы. `npm run mcp:smoke` проверяет оба поколения протокола на обоих транспортах.

### ADR-010: Схемы ответов инструментов

- **Контекст**: опубликованная `outputSchema` описывает успешный `structuredContent`.
- **Решение**: Ajv проверяет успешные ответы перед отправкой клиенту. Сервер отправляет короткий текст в `content` и полные данные в `structuredContent`. При нарушении схемы сервер возвращает ошибку инструмента и просит проверить результат записи перед повторным вызовом.

Каталог хранит контракт каждого инструмента и ключ обработчика в одной записи. Проверка ответов Public API допускает новые поля и отклоняет непригодные обязательные ID до выполнения логики инструмента.

### ADR-011: Чтения повторяются, записи никогда

- **Контекст**: один обрыв соединения или ответ 5xx раньше ломал чтение, и клиенту приходилось повторять вызов вручную. Автоматически повторять запись небезопасно, потому что первый запрос мог уже примениться.
- **Решение**: `teletypeRequest` повторяет транзиентные сбои на GET (5xx и обрывы сети) с быстрым backoff до 3 секунд и учитывает `Retry-After`. POST не повторяется никогда. `TeletypeApiError` несёт HTTP-статус, а граница диспетчера превращает его в подсказку: повторите вскоре для временных сбоев, проверьте токен для 401 и 403.
- **Результат**: короткие сбои Teletype заживают без нового вызова. Неудавшаяся запись не повторяется сама, решение о повторе клиент принимает заново вместе с `confirm`.

### ADR-012: Общие подсказки резолверов и отказ от записи при неопределённой группе

- **Контекст**: каждый инструмент раньше форматировал собственные списки кандидатов для нераспознанных имён каналов, операторов, клиентов, категорий и групп. Запись в группу при неудачном резолве отправляла сырой запрос как ID.
- **Решение**: `candidate-hints.ts` формирует до пяти кандидатов для каждого резолвера. `manage_operator_group` останавливается с ошибкой, если имя группы не распознано, потому что кэш метаданных превращает транспортные ошибки в пустой список.
- **Результат**: одинаковые подсказки во всех инструментах, а временный сбой `/groups` не может перенаправить запись на чужой или несуществующий ID.

## 3. Границы безопасности

1. **Токены**: токены Teletype API не включаются в результаты инструментов и схемы вывода.
2. **Локальные файлы**: пути вложений в режиме stdio разрешаются через `realpath` и сверяются со списком разрешённых каталогов. На Linux открытый файл дополнительно проверяется по дескриптору. На других платформах используйте закрытые для других пользователей каталоги, чтобы они не могли менять компоненты пути во время чтения.
3. **Лимиты запросов**:
   - Ограничение параллельных запросов на токен с хешированием ключей по SHA-256.
   - Ограничение размера ответа API (`maxResponseBytes`, по умолчанию 5 МБ).
   - Короткие таймауты сетевых запросов (`requestTimeoutMs`, по умолчанию 15с).
