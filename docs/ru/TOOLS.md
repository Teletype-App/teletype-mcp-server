# Справочник инструментов

Все 17 инструментов MCP-сервера Teletype: что делает каждый, какие параметры принимает и когда требует подтверждения. Та же информация доступна и в рантайме от самого сервера. При сомнениях, что активно, сначала вызовите `get_capabilities`.

## Карта инструментов

| Инструмент | Набор | Меняет данные | Нужен `confirm` |
| --- | --- | --- | --- |
| `find_conversations` | conversations | нет | нет |
| `list_clients` | conversations | нет | нет |
| `find_messages` | conversations | нет | нет |
| `lookup_client_profile` | conversations | нет | нет |
| `read_conversation_thread` | conversations | только с `mark_seen: true` | только для `mark_seen` |
| `read_client_history` | conversations | нет | нет |
| `resolve_conversation` | conversations | да | да |
| `send_reply_to_client` | messaging | да | да (кроме `dry_run`) |
| `create_dialog_by_phone` | messaging | да | да (кроме `dry_run`) |
| `send_whatsapp_template` | messaging | да | да (кроме `dry_run`) |
| `manage_sent_message` | messaging | да | да |
| `annotate_client_record` | messaging | да | да |
| `list_workspace_metadata` | admin | нет | нет |
| `get_project_status` | admin | нет | нет |
| `manage_operator_group` | admin | да | да |
| `configure_project_webhook` | admin | да | да |
| `get_capabilities` | meta | нет | нет |

## Наборы инструментов (toolsets)

Каждый инструмент входит ровно в один набор. Набор `meta` активен всегда, чтобы агент в любой момент мог спросить сервер, что доступно.

| Набор           | Назначение                                                |
| --------------- | --------------------------------------------------------- |
| `conversations` | Поиск, чтение и закрытие диалогов, профили клиентов       |
| `messaging`     | Отправка и управление сообщениями, аннотирование клиентов |
| `admin`         | Метаданные воркспейса, статус проекта, операторы, вебхуки |
| `meta`          | Самоописание сервера (`get_capabilities`)                 |

Ограничьте активные наборы без изменения кода:

```bash
# CLI-флаги (stdio и http)
teletype-mcp-server --stdio --read-only --toolsets conversations,messaging

# или переменные окружения
TELETYPE_MCP_READ_ONLY=true
TELETYPE_MCP_TOOLSETS=conversations,admin
```

- `TELETYPE_MCP_TOOLSETS` принимает список через запятую. Неизвестное имя падает на старте со списком допустимых наборов, повторы убираются.
- `TELETYPE_MCP_READ_ONLY=true` вообще не регистрирует пишущие инструменты. У этого флага приоритет над `TELETYPE_MCP_TOOLSETS`. В режиме read-only `read_conversation_thread` доступен, но `mark_seen: true` отклоняется с уведомлением вместо изменения данных.
- Фильтрация происходит на старте сервера, до `tools/list`: отфильтрованные инструменты клиент вообще не видит, а не получает отказ.

## Подтверждение и dry-run

Пишущие инструменты требуют `confirm: true` в аргументах. Флаг снижает риск случайных вызовов. MCP-клиент по-прежнему сам отвечает за авторизацию и согласие пользователя.

`send_reply_to_client` и `send_whatsapp_template` принимают `dry_run: true`, чтобы найти получателя, подготовить сообщение или шаблон и вернуть цель (клиент, телефон, канал, диалог) вместе с `side_effects` без отправки. `create_dialog_by_phone` принимает `dry_run: true`, чтобы показать цель и возможные изменения без создания или назначения диалога. Для этих предварительных проверок `confirm` не нужен.

Каждый инструмент публикует `outputSchema`. Краткий текст в `content` даёт основной результат и ссылки. Полный результат лежит в `structuredContent`, проверяемом по схеме. Частичные записи возвращают ошибку со списком применённых действий и сбоев (`partial_errors`). Если вызов к API всё же падает, ошибка несёт подсказку: повторите вскоре для временных сбоев, проверьте токен для ошибок авторизации.

## conversations

### `find_conversations`: Поиск диалогов

Ищет диалоги по статусу, каналу, типу канала, клиенту, тегам, оператору, категории или текстовому запросу. Каждый результат содержит `link_to_dialog`, показывайте его кликабельной Markdown-ссылкой. Пагинация через `page`/`limit`. Ответ сообщает `has_more` и `next_page_hint`.

| Параметр | Описание |
| --- | --- |
| `status` | `open` (по умолчанию) / `close` / `unanswered` / `all`. Для разбора очереди берите `unanswered`. |
| `channel` | Имя канала или его тип (`telegram`, `whatsapp_teletype`, `email`, …), определяется автоматически. |
| `channel_type` | Явный фильтр по типу канала. |
| `tags` | Имена тегов (совпасть должны все). Частично найденный список продолжит работу по найденным, а исключённые теги попадут в `notices`. |
| `operator` | Имя оператора (полностью или частично) либо `unassigned`. |
| `client` | Имя, телефон, email или client_id. |
| `category` | Точное имя категории. Сначала получите список через `list_workspace_metadata(resource: "categories")`. |
| `query` | Поиск без учёта регистра по последнему сообщению или имени клиента. |
| `limit` / `page` | Размер страницы (по умолчанию 20, допустимо от 1 до 100) и номер страницы (по умолчанию 1). Страницы без результатов возвращают пустой список. |
| `response_format` | `concise` (по умолчанию) даёт краткий текст, `detailed` добавляет в текст поля каждого элемента. `structuredContent` всегда содержит все поля. |

### `list_clients`: Список клиентов

Возвращает страницу клиентов. Необязательный `phone` ищет по части номера без изменения данных. `page` и `limit` по умолчанию равны 1 и 20. Пока `has_more` равен true, продолжайте с `next_page`. Public API не предоставляет здесь фильтры по имени и email.

### `find_messages`: Поиск сообщений

Возвращает сообщения проекта или ограничивает их через `dialog_id`, `client_id`, `channel` и `only_active`. `page` и `limit` по умолчанию равны 1 и 50. Необязательный `query` проверяет текст только на полученной странице API. Пока `has_more` равен true, продолжайте с `next_page` прежде чем считать, что старого сообщения нет. `total_api_items` считает сообщения до локального поиска текста. У `/messages` нет полнотекстового фильтра или фильтра по дате. Ответ содержит ID диалога и сообщения, полный текст в `structuredContent` и ссылку на сообщение, если API вернул ID обращения.

### `lookup_client_profile`: Профиль клиента

За один вызов возвращает контакты, теги, кастомные поля, свежие заметки и последние диалоги со ссылками. Принимает имя, телефон, email или client_id. Неоднозначные имена дают список кандидатов.

| Параметр | Описание |
| --- | --- |
| `client` | Имя, телефон (в любом формате), email или client_id. |
| `include_dialog_history` | Включить последние 5 диалогов (по умолчанию true). |
| `include_notes` | Включить заметки операторов (по умолчанию true). |
| `response_format` | `concise` (по умолчанию) даёт краткий текст, `detailed` добавляет в текст поля каждого элемента. `structuredContent` всегда содержит все поля. |

### `read_conversation_thread`: Чтение диалога

Читает сообщения в хронологическом порядке: авторы, вложения, ответы, статусы доставки, время. Также возвращает канал, клиента, оператора и категорию. По умолчанию только чтение.

| Параметр | Описание |
| --- | --- |
| `dialog_id` | ID диалога из `find_conversations`. |
| `client` | Альтернатива `dialog_id`: берётся последний диалог клиента. |
| `messages_limit` | Сколько свежих сообщений вернуть (по умолчанию 50, допустимо от 1 до 200). |
| `mark_seen` | Отметить диалог прочитанным в панели Teletype. Требует `confirm: true`. В режиме read-only чтение проходит, а отметка отклоняется с уведомлением. |
| `confirm` | Подтверждает `mark_seen`. |
| `include_sessions` | История сессий: даты, операторы, статусы, категории. |
| `session_id` | Расширенные данные одной сессии. |
| `include_group_clients` | Участники группового чата (по умолчанию false). |
| `response_format` | `concise` (по умолчанию) даёт краткий текст, `detailed` добавляет в текст поля каждого элемента. `structuredContent` всегда содержит все поля. |

### `read_client_history`: История клиента

Читает недавние диалоги клиента одним вызовом: последние диалоги со срезом сообщений, каналами и ссылками. Используйте, чтобы собрать контекст по клиенту за несколько диалогов перед ответом. Полные метаданные одного диалога читаются через `read_conversation_thread`.

| Параметр | Описание |
| --- | --- |
| `client` | Имя, телефон, email или client_id. |
| `dialogs_limit` | Сколько диалогов вернуть, от 1 до 5 (по умолчанию 3). |
| `messages_per_dialog` | Сколько сообщений на диалог, от 1 до 20 (по умолчанию 10). |
| `response_format` | `concise` (по умолчанию) даёт краткий текст, `detailed` добавляет в текст поля каждого элемента. `structuredContent` всегда содержит все поля. |

### `resolve_conversation`: Обработка диалога

Закрывает диалог или передаёт его оператору. По умолчанию закрывает. `close: false` оставляет диалог открытым, если нужно только переназначить оператора, сменить категорию или добавить теги. `mark_answered` / `mark_unanswered` помечают открытые обращения без закрытия. Для закрытия категория не нужна. Не передавайте `category`, если пользователь её не просил. Если просил, сначала возьмите точное имя из `resource: "categories"`.

| Параметр                            | Описание                                                   |
| ----------------------------------- | ---------------------------------------------------------- |
| `dialog_id`                         | ID диалога.                                                |
| `assign_operator`                   | ID/имя/email оператора или `auto` для автовораспределения. |
| `close`                             | Закрыть после остальных действий (по умолчанию true).      |
| `category`                          | Необязательное точное имя категории.                       |
| `add_tags`                          | Теги клиента при закрытии.                                 |
| `final_note`                        | Финальная заметка о клиенте при закрытии.                  |
| `mark_answered` / `mark_unanswered` | Пометки обращений без закрытия.                            |
| `confirm`                           | Обязателен.                                                |

## messaging

### `send_reply_to_client`: Отправка ответа клиенту

Отвечает в существующий диалог, начинает новый через канал (опционально `auto_close: true`) или создаёт пустой диалог (`create_dialog_only: true`). Поддерживает текст, шаблоны проекта с подстановками `{{переменная}}`, публичные URL вложений, локальные пути (только stdio, по умолчанию выключено) и цитирование через `reply_to_message_id`. По умолчанию помечает диалог отвеченным. Результат сообщает о приёме API, а не о подтверждённой доставке.

| Параметр | Описание |
| --- | --- |
| `recipient_dialog_id` | Существующий диалог для ответа. Перекрывает client/channel. |
| `client` / `channel` | Для нового диалога: получатель и канал отправки. |
| `text` | Текст сообщения, не нужен при `template_name`. |
| `template_name` / `template_variables` | Шаблон проекта и подстановки вида `{"name": "Иван"}`. |
| `attachment_url` | Публичный URL, который Teletype скачает и отправит. |
| `attachment_path` | Локальный абсолютный путь. Только доверенный stdio, нужен `ENABLE_LOCAL_UPLOADS`. |
| `reply_to_message_id` | Цитируемое сообщение. |
| `mark_dialog_answered` | По умолчанию true. |
| `auto_close` | Автозакрытие сессии, открытой отправкой через канал. |
| `create_dialog_only` | Создать диалог без отправки текста. |
| `dry_run` | Показать найденную цель и отрендеренное сообщение без отправки. `confirm` не нужен. |
| `confirm` | Обязателен, кроме `dry_run: true`. |

### `create_dialog_by_phone`: Создать или найти диалог по телефону

Вызывает `/dialog/create` с номером телефона и подходящим каналом, не отправляя сообщение. Это запись. API может вернуть существующий диалог и назначить владельца проекта его оператором, если диалог открыт. Поэтому результат сообщает `created_or_found`, а не гарантирует создание нового диалога. Для проверки номера без изменений используйте `list_clients(phone=...)`.

| Параметр  | Описание                                      |
| --------- | --------------------------------------------- |
| `phone`   | Номер получателя.                             |
| `channel` | Название, тип или ID подходящего канала.      |
| `dry_run` | Показать цель и возможные эффекты без записи. |
| `confirm` | Нужен для реального вызова.                   |

### `send_whatsapp_template`: Отправка WABA-шаблона

Отправляет одобренный WABA-шаблон в существующий диалог Edna WhatsApp вне 24-часового сервисного окна. ID шаблона берётся из импортированных WABA-шаблонов проекта, а не из списка быстрых ответов, который возвращает `list_workspace_metadata`.

| Параметр | Описание |
| --- | --- |
| `channel_id` | ID WhatsApp-канала из `resource: "channels"`. |
| `dialog_id` | ID диалога. |
| `template_id` | ID WABA-шаблона, импортированного из Edna. |
| `template_params.text_variables` | Значения для переменных `{{1}}`, `{{2}}` в тексте. |
| `template_params.header_variables` / `button_variables` | Значения переменных шапки и кнопок. |
| `dry_run` | Проверить параметры и показать цель без отправки. `confirm` не нужен. |
| `confirm` | Обязателен, кроме `dry_run: true`. |

### `manage_sent_message`: Управление сообщением

Редактирует, удаляет или переотправляет сообщение оператора.

| Параметр     | Описание                                                  |
| ------------ | --------------------------------------------------------- |
| `message_id` | Из `send_reply_to_client` или `read_conversation_thread`. |
| `action`     | `update` / `delete` / `resend`.                           |
| `text`       | Новый текст, обязателен для `update`.                     |
| `confirm`    | Обязателен.                                               |

### `annotate_client_record`: Аннотирование клиента

Один вызов обновляет метаданные клиента или диалога: теги, заметку, кастомные поля, поля идентификации или категорию диалога. Если одна операция падает, остальные могли примениться. Проверьте `applied` и `partial_errors` перед повтором.

| Параметр | Описание |
| --- | --- |
| `client` | Обязателен для операций с тегами/заметками/полями. |
| `dialog_id` | Обязателен только при изменении `dialog_category`. |
| `add_tags` / `remove_tags` | Имена добавляемых и удаляемых тегов. |
| `note` / `delete_note_id` | Текст новой заметки или ID заметки на удаление. |
| `custom_fields` | `{"order_id": "1234", "segment": "B2B"}`. Заменяет значения по ключу. |
| `name` / `phone` / `email` | Обновление идентификации. |
| `additional_payload` / `force_additional_payload` | Доп. данные клиента. Перезаписываются целиком, без слияния. |
| `dialog_category` | Имя категории для диалога. |
| `confirm` | Обязателен. |

## admin

### `list_workspace_metadata`: Метаданные воркспейса

Возвращает каналы, теги, категории, шаблоны быстрых ответов, папки шаблонов, операторов или группы операторов. Результаты кэшируются на минуту. Предпочитайте один `resource` усечённому `all`.

| Параметр | Описание |
| --- | --- |
| `resource` | `channels` / `tags` / `categories` / `templates` / `template_directories` / `operators` / `groups` / `all`. |
| `group_id` | ID или имя группы для данных `/group/view/:groupId`. |
| `channel_type` / `only_active` | Фильтры каналов. |

### `get_project_status`: Статус проекта

Состояние проекта одним вызовом: баланс и биллинг, доступность операторов, статус Public API, активность каналов, ошибки вебхуков плюс выведенные предупреждения.

| Параметр           | Описание                                                   |
| ------------------ | ---------------------------------------------------------- |
| `aspect`           | `technical` / `financial` / `team` / `all` (по умолчанию). |
| `include_warnings` | Блок выведенных предупреждений (по умолчанию true).        |
| `operator_details` | Расширенный список операторов для `team`.                  |

### `manage_operator_group`: Управление группой операторов

Добавляет и убирает участников, привязывает и отвязывает каналы, назначает супервизоров и управляет видимостью чужих диалогов в канале. Названия групп берите из `list_workspace_metadata(resource='groups')`. Если группа не распознана однозначно, инструмент останавливается без записи.

| Параметр | Описание |
| --- | --- |
| `action` | `add_member` / `remove_member` / `add_channel` / `remove_channel` / `set_supervisor` / `set_channel_visibility`. |
| `group` | Имя или ID группы. |
| `operator` | Для действий с участниками и `set_supervisor`. |
| `channel` | Для действий с каналами и `set_channel_visibility`. |
| `is_supervisor` | Выдать или снять доступ супервизора. |
| `can_view_other_dialogs` | Видимость диалогов на уровне канала. |
| `confirm` | Обязателен. |

### `configure_project_webhook`: Настройка вебхука

Задаёт URL публичного вебхука проекта и список активных событий.

| Параметр        | Описание                                                              |
| --------------- | --------------------------------------------------------------------- |
| `webhook_url`   | URL-приёмник. Пустая строка убирает текущий.                          |
| `active_events` | События для активации. Пустой или отсутствующий список выключает все. |
| `confirm`       | Обязателен.                                                           |

## meta

### `get_capabilities`: Возможности сервера

Возвращает активную карту инструментов сервера: `project` (имя и домен), `read_only`, `active_toolsets`, каждый зарегистрированный инструмент с набором и флагом `writes_data`, `disabled_tools`, локаль и доступность локальных вложений. Вызывайте первым, когда непонятно, какие инструменты или фильтры активны, например после подключения с `--read-only` или `--toolsets`.

Без параметров. Доступен всегда, независимо от конфигурации наборов.
