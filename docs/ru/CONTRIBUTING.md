# Участие в разработке

Для локальных npm-команд используйте Node.js 20.19+, 22.13+ или 24.x. Устанавливайте зависимости через `npm ci`. Не смешивайте несвязанные изменения в одном запросе на включение изменений. Добавляйте тесты для наблюдаемого поведения. Во время разработки запускайте `npm run check:fast`. В CI выполняется `npm run check` с покрытием и адресными мутационными проверками.

Не добавляйте в Git API-токены, данные клиентов и рабочие логи. Инструменты, которые меняют данные, должны требовать явного подтверждения и сообщать о частично выполненных операциях.

Если меняете ответ инструмента, обновляйте `outputSchema` и `structuredContent` вместе. После изменений MCP-сервера или транспорта запускайте `npm run mcp:smoke`. Команда проверяет рукопожатия версий 2025 и 2026-07-28 через HTTP и stdio клиентом SDK. Та же команда проверяет тестовый MCP-режим. При изменении флагов CLI обновляйте примеры подключения в `examples/clients/`.

Контракт инструмента меняйте в `src/tool-catalog.ts`. При изменении ответа Public API оставляйте новые поля допустимыми и проверяйте только поля, которые использует инструмент. Перед выпуском запускайте `npm run package:smoke` на поддерживаемой версии Node.js. Команду `npm run mcp:conformance` запускайте на Node.js 24, потому что внешняя утилита conformance не работает на Node.js 20.

Текст для MCP-клиентов добавляйте под одинаковым ключом в английский и русский каталоги в `src/locales/`. В обработчике вызывайте `t(key, params)`. Имена и типы параметров должны совпадать в обоих каталогах. `npm run typecheck` проверяет форму каталогов. В строках для клиента запрещены длинные тире и точки с запятой в обоих языках, это проверяет тест всего каталога в `src/i18n.test.ts`. После правок текста перезапускайте `npm run check:fast`.

Для `npm run eval:model` переменная `EVAL_SPLIT` выбирает `core`, `heldout` (кейсы, которые не использовались для настройки промптов) или `all`.

## Релизы

Процесс публикации GitHub принимает теги вида `v<версия из package.json>`. Перед публикацией он сверяет тег с версиями пакета, `server.json` и собранной программы CLI. Настройте [npm Trusted Publisher](https://docs.npmjs.com/trusted-publishers/) для публичного репозитория GitHub и файла `release.yml`, чтобы разрешить прямой `npm publish`. На время перехода остаётся доступен секрет репозитория `NPM_TOKEN`. Образ Docker и GitHub Release публикуются только после успешной публикации в npm.

Перед первым публичным тегом:

1. Откройте доступ к `https://github.com/Teletype-App/teletype-mcp-server` и проверьте адрес репозитория в `package.json` и `server.json`.
2. Запустите `https://mcp.teletype.app/mcp` по HTTPS. Выполните `TELETYPE_API_TOKEN=... npm run hosted:smoke` с токеном проекта, чтобы проверить MCP-подключение и чтение через Teletype Public API. Команда не печатает данные проекта или токен.
3. Убедитесь, что имя `teletype-mcp-server` свободно в npm, и настройте Trusted Publisher. Поле `mcpName` в `package.json` должно совпадать с именем в `server.json`.
4. Обновите версии пакета и записи для реестра вместе. Выполните `npm run check`, `npm run package:smoke`, `npm run mcp:conformance`, `npm run bundle:mcpb` и `GITHUB_REF_NAME=v<версия> npm run release:verify`. Проверьте `server.json` по официальной схеме из его поля `$schema`.

После публикации npm процесс выпуска вызывает `publish-registry.yml`. Он сверяет тег, ждёт появления npm-версии и публикует `server.json` через [GitHub OIDC](https://github.com/modelcontextprotocol/registry/blob/main/docs/modelcontextprotocol-io/github-actions.mdx). Отдельный секрет для Registry не нужен. При ошибке запустите **Publish MCP Registry** вручную с существующим тегом релиза. После выпуска проверьте адреса npm, Registry, Docker и `.mcpb`. Удалённый MCP-эндпоинт должен уже работать.

Обновляйте версии манифеста LobeHub, расширения Gemini, трёх манифестов плагина, маркетплейсов Claude и Cursor, MCPB и закреплённых npm-запусков вместе с версией пакета. `release:verify` проверяет их согласованность. При изменении инструментов, ресурсов или промптов обновляйте массивы возможностей в манифесте LobeHub.
